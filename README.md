# PathSnap: GPS Map Matching

A team project for the PathSnap hackathon. It maps noisy GPS observations to directed road-segment candidates, scores candidates with a trained classifier, and reconstructs a coherent route with HMM/Viterbi decoding.

## Current status

- Person 1 preprocessing and candidate feature generation are implemented in `pathsnap_person1.py`.
- Five candidate-scoring models were compared using a 64/16 trip-level holdout in `train_models.py`.
- Five-fold GroupKFold results by trip are generated by `cross_validate_models.py`.
- Current labels are spatial route-alignment heuristics. Results are provisional and must be described as such until alignment is independently reviewed.
- The provisional model choice is Logistic Regression by observation-level top-1 accuracy; Hist Gradient Boosting has stronger candidate macro-F1 and log-loss scores.

## Data placement

Place the supplied data locally under `data/` with `train/` and `student_test/` subfolders. The dataset is excluded from Git by `.gitignore`; do not publish it or evaluator data.

## Environment

Python 3.12 or compatible, NumPy, and scikit-learn. Install dependencies with:

```powershell
python -m pip install -r requirements.txt
```

## Generate candidate features

From this project directory:

```powershell
python pathsnap_person1.py ".\data" ".\features" train
```

This creates `features/train_candidates.csv`. The generated candidate table is excluded from Git because it is large and reproducible.

## Compare models and cross-validate

```powershell
python train_models.py
python cross_validate_models.py
```

These commands use training trips only and split by trip. They write comparison summaries under `features/`. `student_test` is reserved for development-stage evaluation after model selection; evaluator-testing data and labels must remain outside the development pipeline.
